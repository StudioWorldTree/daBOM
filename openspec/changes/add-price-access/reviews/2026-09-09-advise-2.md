## Independent take (written before design.md / tasks.md / delta / prior review)

Sources: proposal Why, living spec stub, `schema.ts:69-88`, `bom.ts:24-26` and `bom.ts:84-100`. Persisted as `blind-take.md` in the spawn dir.

1. Pin: quote rows are append-only observations. A refresh inserts a new row; it never UPDATEs price or checkedAt on an old one.
2. Pin: every row carries method (manual | api | scrape | seed), a source URL, and checkedAt. Seeded rows get method=seed and never a fabricated date.
3. Pin: ladder is manual/seed → vendor API → page scrape, per vendor, and no adapter falls through to scrape silently.
4. Pin: roll-up picks the newest priced row per (item, vendor), then the preferred vendor. isPreferred is a vendor choice, not a row that survives refresh.
5. Pin: pickQuote's "first priced quote" fallback is undefined order today (no ORDER BY in listBom). The change must make it deterministic.
6. Refuse: any PATCH on a quote's price. Corrections are a new row with method=manual.
7. Refuse: a stale quote rolling up as current with nothing saying so. Roll-up should expose an asOf or a stale flag.
8. Refuse: deleting seed rows on first refresh; they are the provenance of where numbers came from.
9. Tradeoff: append-only grows the table and pickQuote needs latest-per-vendor instead of a flat find. Accept; a mutable row plus history table doubles the schema for no gain.
10. Open question the author must answer: how does isPreferred survive a refresh under append-only? On the row, a new row is not preferred. It should move to (item, vendor) or be inherited.

## Pins the act must carry (not blocking, one sentence each)

### Pin A — roll-up rule text contradicts its own scenario

Design and delta say: "latest row per vendor, then preferred vendor; if no preferred vendor, rank methods, then newest." Read literally, step one picks the Sep 8 crawl row for Digi-Key and discards the Sep 1 api row before method rank runs. The scenario "API beats a later crawl" then fails. The scenario is right and the sentence is misordered. Reword: within a vendor, best method rank then newest; across vendors, preferred vendor, else best method rank, then newest. Steelman: "latest per vendor" may have meant "best per vendor". Say so in the spec, because the fold copies the sentence.

### Pin B — preferred vendor with no price

Seed `cti-msg103` (catalog.ts:223) has a preferred CTI row with null priceCents. Current pickQuote skips it because it requires a price. The new rule says "then preferred vendor" with no price guard. Pin: the preferred vendor wins only if its chosen row is priced; otherwise fall to method rank. Otherwise the roll-up regresses on the existing seed.

### Pin C — PATCH isPreferred on a superseded row

Supersede clears the old row's flag, but PATCH may set isPreferred on any row, including one that is no longer latest for its vendor. Roll-up then loses the flag at the latest-per-vendor step. Pin one: PATCH isPreferred on a non-latest row is 422, or preferred is read from any row of that vendor. The first is simpler.

### Pin D — asOf on roll-up

Under Pin A a March api row beats a September crawl for the same vendor forever, by design. That is defensible only if the total says how old it is. Add `asOf` = min checkedAt across chosen priced quotes to the rollup DTO. Not a schema change, so not blocking, but it is what makes "honest roll-up" in the Why true.

### Minor

- Supersede is insert plus update of the previous row; do it in one transaction.
- `DELETE /items/{sku}` still deletes quotes (app.ts:195). Fine: the item is gone. Not append-only history, but out of scope.
- Rows without checkedAt sort last under "then newest".

## Verdict reasoning

The ladder is pinned, the refresh now changes the total, and PATCH cannot rewrite money. Those were the three reasons for the send-back and each has a scenario. What remains is four sentences that sharpen a rule that already exists, none of which reverses a decision. A second send-back for wording is ceremony. Accept. Pins A to D are added to tasks.md as reader-added lines so act carries them.
