## Independent take (written before design.md / tasks.md)

Sources: proposal Why, living spec stub, `schema.ts:32-59`, `bom.ts:127-140`, `bom.ts:203-225`, catalog grep.

1. Pin: floor is a column on `items`, orthogonal to `kind`. Kind is taxonomy; floor is "does this shop open the box". Do not add a fourth kind.
2. Pin: explode stops on floor, not on kind. A SOM tagged `assembly` with a die under it must not be walked.
3. Pin: one leaf predicate. Today `kind === 'part'` is branched in three places (explode 135, rollup 204 and 221). Floor must replace all three or rollup and partCount drift from explode.
4. Refuse: ordinal floor (0..n). Nobody can order "fabricate PCB" against "assemble kit". Use a named enum.
5. Refuse: floor on `bom_lines`. Opening a child is a property of the child in this shop, not of one parent line.
6. Refuse: dropping or overloading `kind`. DTOs, list filter, and the kits endpoint depend on it.
7. Tradeoff: a per-item floor is global per shop. Same SKU bought in one product and built in another makes the column lie. Accept now; per-line override is a later escape hatch, not this change.
8. Ingest guard must exist at write time. If a buy-floor item can still receive `bom_lines` children, agents will store the die and explode merely hides it. The delta must say what an insert under a buy-floor parent does.
9. SKU kebab `manufacturer-mpn`: pin normalization (case, non-alnum collapse) and collision rule. Changing PKs on the seed is a migration, not a retag.
10. Test I want: assembly -> `t4000-som` (floor buy) -> fake grandchild. Explode emits the SOM, never the grandchild. T4000 stays a buy-leaf.

## Comparison (after design.md, tasks.md, delta, steer.md)

Matches the take on every pin and refuse: floor is a named enum column on
`items`, orthogonal to `kind`; explode and roll-up stop on floor; nothing on
`bom_lines`; `kind` untouched; write-time 409 under a non-assemble parent;
SKU regex pinned with 422; T4000 named `buy`. Design is sound. Accept.

Steelman against my take, and what the author still owes:

**Backfill is the hole (tasks, not design).** Design says default `buy`
is for *new* items and names kit-prod / asm-thor-sandwich as `assemble`.
But `catalog.ts` has eight `assembly`/`kit` parents (lines 734-804) with no
floor, and `seed.ts` inserts their `bom_lines` directly through drizzle, so
the API 409 never sees them. With `DEFAULT 'buy'` and seed retag deferred to
`add-floor-seed`, every existing kit explodes to nothing the moment this
lands. Retagging the catalog is out of scope; deriving is not. Migration
and seed must set `floor = 'assemble'` for any SKU that is a parent in
`bom_lines`. Added to tasks.md as a reader line.

**Second door on the same invariant.** Delta pins "non-assemble items have
no children" at line insert. PATCH floor to `buy`/`foundry` on an item that
already has children is the other door. Added to tasks.md; the delta's
Requirement already implies it.

**Three branch sites, not one.** `bom.ts` tests `kind === 'part'` at 135
(explode), 200 (partCount), and 204 (rollup leaf sum). Tasks say "explode /
roll-up stop"; be sure 200 and 204 flip to the floor predicate too, or a
`kind=assembly, floor=buy` complete-camera is a leaf in explode and invisible
in cost. Best as one exported `isLeaf(item)`.

**Kind and floor are independent.** Design never says whether
`kind=kit, floor=buy` (a bought dev kit) or `kind=part, floor=assemble` is
legal. Both should be, and the `/kits` endpoint will then list bought kits
with an empty BOM. Fine, but say it so ingest does not invent a cross-check.

**Foundry now.** Two values with identical runtime behaviour is a smell I
would normally refuse. Steelman: it is vocabulary reservation so an agent
can record "die breakdown known, do not descend" without a schema change
later. Accepted on that reading; nothing in this change may branch on
`foundry` differently from `buy`.

**Global floor per shop.** Still a tradeoff, unaddressed, correctly not
solved here. Per-line override stays a later escape hatch.
