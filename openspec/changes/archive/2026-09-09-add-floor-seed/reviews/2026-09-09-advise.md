## Blind take (written before opening proposal/tasks/delta)

1. Pin: `floor` becomes a **required** key on `SeedItem` (not optional, no default). The Why is that the crib is silent; an optional key with a `buy` default keeps it silent for the 40 leaves.
2. Pin: every one of the 8 `asm-*`/`kit-*` rows is tagged `assemble`; all 40 `kind: 'part'` rows are tagged `buy`. Today the backfill and an explicit tag agree, so this is a no-behavior-change retag and must stay that way.
3. Pin: the upsert `set` list in `seed.ts:33-50` must include `floor`. Without it a non-force re-seed on an existing DB never applies the catalog value.
4. Pin: the post-insert backfill at `seed.ts:71-76` stops silently flipping. Either delete it, or turn it into an assertion that fails seed when a `bom_lines` parent is tagged anything but `assemble`. A silent override under an explicit field is how the crib got silent in the first place.
5. Pin: a test that walks `seedBoms` and asserts every parent's catalog `floor` is `assemble`, and that `t4000-som` GET bom is empty after seed.
6. Refuse: any seed row tagged `foundry`. The spec reserves it; nothing in this catalog is fabbed here.
7. Refuse: deriving floor from `kind` in code (`kit`/`assembly` -> `assemble`). Schema comment says they are orthogonal. The tag lives in data.
8. Refuse: adding children under `t4000-som`, `rogue-t5`, `pyxis-*`, `rv1126b-turret`, `rv1126b-core`, or `poe-switch-at`. Buy leaves; the die breakdown is "later" and would be a 409 by the living spec.
9. Tradeoff: the two resin shells are printed in-house (vendor `print`) but carry a priced quote. `assemble` with no children rolls up to zero and loses the quote; `buy` keeps the cost but reads oddly for a part we make. I'd tag `buy` with a note until resin+labor is modeled as children.
10. Tradeoff: no new migration. `0001` already backfilled older DBs; this change is data plus the upsert fix.

## Compare

The change answers 2, 7, 8, 10 cleanly. Proposal, steer, and delta all hold
T4000 as a buy leaf with no die, the assemble set is exactly the 8 parents,
floor is data not a `kind` rule, and there is no migration. Good.

It does not answer 1, 4, 5. Those three are one hole, below.

Take 3 is weaker than I wrote it: force-reseed deletes first, non-force
returns early on a populated DB, so the upsert `set` list is effectively
unreachable today. Downgraded to a hygiene note.

Take 6 and 9 are unanswered but not blocking. Notes below.

## The hole: acceptance cannot tell tagged from untagged

Every test in `tasks.md` passes against today's code with zero catalog
change:

- `GET /items/t4000-som/bom` is already empty (default `buy`).
- `GET /items/kit-prod/bom?explode=true` already explodes to buy leaves (backfill).
- Those SKUs already return `floor` (column exists since `0001`).
- `app.test.ts:120` already asserts kits are `assemble` and the SOM is `buy`, reading the DB after seed.

No test imports `seedItems`. So the backfill at `seed.ts:71-76`, which task 4
keeps as "a safety net", would silently correct a missing or wrong tag on any
parent, and the DB-level tests would stay green while the crib stays silent.
That is the Why, unfixed, with a green build on top of it. A change whose
acceptance cannot fail before and pass after is not a change.

Steelman for task 4 as written: LEARNINGS from `add-compose-schema` say the
net saved seeded kits from exploding to nothing when `floor` landed, and the
API already enforces the parent rule at runtime via 409. Keeping the net is
fine. What is not fine is keeping it with nothing that proves it is inert on
the shipped seed.

### What closes it (author picks the shape)

- `SeedItem` type requires `floor: (typeof itemFloors)[number]`. A row without it fails typecheck. This is take 1 and it costs one line.
- One catalog-level test that imports `seedItems` and `seedBoms` from `catalog.ts`, not the DB: every `seedBoms` parent has `floor === 'assemble'` in `seedItems`; every non-parent has `floor === 'buy'`; no row is `foundry`. This fails today and passes after.
- Task 4 reworded: the backfill stays, and the catalog test is what proves it never fires on the seed. Or turn it into a seed-time assertion. Either is acceptable. "Remains a safety net, not the only tag" without a proof is the status quo.

Keep the existing DB-level tests. They are not the acceptance for this change.

## Notes (not blocking)

- Task 1 lists `foundry` as an allowed seed value. Steer says raise floor per SKU when a foundry is contracted. Say `buy | assemble` and leave `foundry` reserved, so the catalog test can refuse it.
- The resin shells (`resin-shell-front`, `resin-shell-rear`) are the one row class the delta does not name. They are `kind: part`, printed in-house, priced. Recommend `buy` with a one-line note; an empty `assemble` rolls up to zero and drops the quote. Name it in tasks so the next reader does not reopen it.
- Hygiene: add `floor` to the upsert `set` list in `seed.ts`. Unreachable today, but a seed that upserts everything except the field this change is about will confuse the next person.
- The delta's "sandwiches" covers `asm-lab-shell`, which is a shell not a sandwich. Fine, but "assemblies" is the word the schema uses.
- `agx-thor-devkit` is a bought kit seeded as `kind: part`. Out of scope for this change (no SKU or kind changes), but it is the schema comment's canonical `kind=kit, floor=buy` example and is not tagged that way. Worth a bead.

## Verdict

Send-back on one hole: the change as specced ships no test that can fail
today. Add the required type on `SeedItem` and a catalog-level test over
`seedItems`/`seedBoms`, and reword task 4 so the safety net is proven inert.
The T4000 leaf and the assemble set are right and should not change.
