## Blind take (written before opening proposal, tasks, steer, or the delta)

1. Pin: the ladder is per vendor, API then crawl then headed, and the posted `method` must be the rung that actually produced the price. A crawl result posted as `api` corrupts roll-up rank, which is the only thing method is for.
2. Pin: failed fetch, login wall, parse miss, out-of-stock-without-price are all "no POST". The server already 422s priceless fetched rows; the skill must not route around that by inventing a price, posting `manual`, or PATCHing an old row.
3. Pin: `checkedAt` is the skill's fetch time, not a date lifted from the page or the seed row.
4. Pin: where the vendor part number comes from. The API needs a Digi-Key/Mouser/Arrow part number per (item, vendor); the bom-quotes spec has only a URL on the quote. If the skill derives it from the prior quote's URL that must be stated, else this is a hole.
5. Pin: price breaks. Distributor APIs return quantity tiers; a quote holds one `priceCents`. The skill must fix a quantity rule (qty 1, or the BOM line qty) and record it, or two runs disagree for no reason.
6. Pin: secrets stay out of the repo. API keys via env; the headed Playwright profile stays local and is not committed.
7. Pin: partial runs. One vendor failing or rate-limiting must not abort the sweep; report per-item outcomes, insert only successes.
8. Refuse: scrape-first for any vendor that has an API. Refuse a single generic "fetch price" that does not distinguish rungs.
9. Refuse: the skill writing to the DB directly. It must go through POST /quotes so the 422 guards and supersede-preferred logic apply.
10. Tradeoff: HTTP-only is right, but it costs a running server and a base URL, and re-running daily on an unchanged price still appends a row. Accept the churn; append-only is the invariant, dedup is a later concern.

## Compare

**Answered by the change.**

- Take 1 and 8, API before crawl before headed: pinned in the delta
  requirement "Quote skill walks the access ladder", in the proposal,
  in steer, and already in ADR-003. Digi-Key, Mouser, Arrow are named
  as API-first; B&H and CTI/WDL start at crawl or headed. Scrape-first
  is not on the table. This is the acceptance hinge and it holds.
- Take 2, failed fetch is not a quote: pinned twice, delta "Login wall
  is not a quote" and task 4. The server-side 422 on priceless fetched
  rows is the backstop and the skill is told not to route around it.
- Take 9, no direct DB writes: delta says SHALL NOT write PGLite,
  proposal says HTTP only, no drizzle. The sibling ingest skill uses the
  same rule, so the two skills will share a base-URL convention.
- Take 10, HTTP-only cost: author accepted the same tradeoff. Fine.
- Take 4, part number source: the proposal says SKU/MPN drives the API
  rung, and `items.mpn` and `items.manufacturer` exist in the schema.
  Steer rules out a new per-vendor table. So the API rung is an MPN
  search against each distributor. Answered, but it opens the hole
  below.

**Not answered. Pinned in tasks.md so the actor does not guess.**

- **Exact-MPN match on the API rung.** An MPN keyword search at
  Digi-Key or Mouser returns fuzzy hits. A near-miss part posted as
  method `api` out-ranks the correct seed or crawl price in roll-up,
  because `api` is the top rung. That is worse than no row. Pin: the API
  rung posts only when the result's manufacturer part number equals
  `items.mpn` exactly; otherwise that rung fails and the ladder moves on.
  Items with a null `mpn` skip the API rung.
- **Quantity tier.** Distributor APIs return price breaks; the quote
  holds one `priceCents`. Pin: unit price at quantity 1, and write the
  tier into `notes` so a later change can switch to BOM-line quantity
  without re-reading history.
- **URL for the crawl rung.** The delta says "crawl of the public
  product page" but seeded B&H, Digi-Key, and Mouser rows carry no URL,
  and the `vendors` table holds only a homepage. Pin: crawl the URL on
  the latest quote row for that (item, vendor) if present; otherwise a
  Firecrawl search on manufacturer plus MPN scoped to the vendor
  domain, and the URL actually fetched goes on the posted row so the
  next run does not search again.

**Notes, no action required.**

- Take 3, `checkedAt`: the schema comment calls it the vendor's date
  and the column is `date`, so the skill posts the fetch date as
  `YYYY-MM-DD`. Postgres will truncate a full timestamp, but posting a
  bare date is cleaner.
- Take 6, secrets: task 2 says "when a key/feed exists", which implies
  env. Say so in the SKILL.md. The headed Playwright profile must not
  land in the repo.
- Take 7, partial runs: the delta scopes the skill to one SKU or MPN
  per call, so sweep semantics are out of scope here. Fine for day one.
- Ladder scope: the delta reads as one ladder per SKU. The bom-quotes
  ladder is per vendor page. They agree in practice because the skill
  should refresh the vendors the item already has quotes for, plus any
  API vendor that exact-matches the MPN. It should not post a Digi-Key
  quote for a part Digi-Key does not carry, which the exact-MPN pin
  prevents.
- Currency: Arrow and Digi-Key return locale-dependent currency. Pin
  the US locale in the client so `currency` stays `USD`.

## Steelman against the take

The author could say the three pins are implementation detail, not
spec, and that the delta is deliberately lean. That is half right. The
quantity tier and the crawl URL source are implementation choices with
a reasonable default, and I have supplied one rather than sending back.
The exact-MPN match is not detail. It is the API-rung analog of "a
failed fetch is not a quote", and without it the top rung can write a
wrong-part price that nothing downstream can detect. That is why it is
pinned rather than noted. None of the three change the shape of the
change, so accept stands.

## Verdict

Accept. API-before-crawl is pinned in the delta, in steer, and in
ADR-003. Failed fetch inserts nothing, HTTP only. Three pins added to
`tasks.md`: exact-MPN match on the API rung, quantity-1 tier recorded
in notes, and URL provenance for the crawl rung.
